Stage-studio is transitioning from single-user (Joel) to first-external-user (his friend **Art**). A "can't be handed to a second user" ticket captures the gap (signing/notarization, first-run permissions onboarding, icon, install artifact) — see [[hotkey-app-build]] for the app itself.

**Why:** the pre-release move-fast calibration (unsigned, no onboarding) was deliberate; the first external user flips it — distribution ceremony now protects something real.

**How to apply:** standing offers from Joel (2026-07-28): his **Apple Developer account** is available for signing/notarization — when blocked on auth, open the browser, take him to the right page, and he'll unlock; he'll supply an **app icon** on request. Shipping-unit question RESOLVED 2026-07-28 via DIG-793 (shaped with Joel): **app-as-engine** — the app is the single recording engine + UI; CLI + /record skill are thin clients routing through it (`--headless` as explicit fallback). Agent-initiated recordings must be visible (distinct pill state) and physically overridable by Joel — that visibility contract is the price of any future autonomous recording.

**Distribution decisions settled 2026-07-29 (Joel):** Art is on **Apple Silicon, recent macOS** → arm64-only stays, floor is **macOS 15 (Sequoia)**, no universal build. Homebrew path = a **cask that installs the .app**, not a formula for the CLI tarball — which reshapes DIG-184 (re-read it before more work lands there; its uncommitted WIP predates app-as-engine). Notarization is done **locally**, not in CI — the signing identity lives on Joel's machine and CI secrets are unjustified ceremony for an audience of one; consequence: `release.yml` needs no change, which also keeps DIG-184's branch conflict-free. **No Sparkle/auto-updater** for the first handoff (a "Check for Updates…" menu item instead), knowingly accepting that an updater can't be retrofitted onto an installed base — fine at one known, reachable user. Keycap contrast in `KbdChip` (~2.6:1) is **intentional recession** — Joel's call, don't "fix" it.

**Reusable distribution facts (verified 2026-07-29, not remembered):** the notarytool keychain profile is **account-scoped, not app-scoped**, so one profile notarizes any of Joel's apps — pass it via `STAGE_STUDIO_NOTARY_PROFILE` to `app/package.sh` rather than hardcoding (the repo is public; don't bake another project's profile name into it). **`DigitalPine/homebrew-tap` already exists** (public) — no new tap repo needed; formulae sit at the repo root but **casks must live in `Casks/`** (`tap.rb` defines `cask_dir` as `path/"Casks"`, no root fallback), so the cask goes at `Casks/stage-studio.rb` and installs as `brew install --cask digitalpine/tap/stage-studio`. Cross-identity is already house precedent there (`exp.rb` is in the DP tap but points at `thebrubaker/exp` releases). The macOS-15 floor should be encoded as `depends_on macos: ">= :sequoia"` so brew refuses a too-old Mac instead of delivering a broken app.

**Gotcha that would have wasted the whole packaging chain:** `swiftc` with **no `-target` bakes the build machine's OS in as the binary's minimum**, silently. It shipped an app claiming `LSMinimumSystemVersion 14.0` around a recorder carrying `minos 26.0` — launches fine here, dyld error in a second user's hands. Fixed in DIG-802; the plist key is only a *claim*, `LC_BUILD_VERSION` is what dyld enforces, so verify with `otool -l <bin> | grep -A4 LC_BUILD_VERSION`, never the plist.
